## 問題與根因

1. 角色根節點快速向上移動，但沒有安排可連續支撐的身體路徑；肩膀超出手臂可達區域後，IK 會把手臂長度限制在上限，手掌便無法留在邊緣。
2. 雙腳在上升中段仍懸空，缺少明確的前腳落點與承重階段，所以看起來像被抬上平台。
3. 只有最終站上平台的功能測試，無法攔截中段滑手、鞋底穿邊與踩穩後滑步。
4. 程序插值只能補間姿勢；先前沒有真人參考與完整動態比對，對發力、重心及節奏的判斷不足。

## 過程中修正的陷阱

- 最初抬身關鍵點讓手掌目標落入兩節手臂最短可達距離之內。調整軀幹／骨盆路徑，讓支撐階段同時滿足最短與最長距離限制。
- 前腳原先向內移動時仍低於平台表面，新增「先抬鞋底、再向內跨」的關鍵點，避免踩入平台側邊。
- 動態障礙測試若等待固定長時間，可能在碰撞中止後連冷卻都已結束，造成錯判；改為每幀觀察離開 CLIMB 的時刻。
- `var plant := ...` 因動態玩家參照無法推導型別，改為明確宣告 `Vector2`。
- 沙盒下圖形 Godot 啟動中止；取得執行授權後用 macOS 圖形渲染器擷取。無頭模式用於功能測試，不能拿 dummy renderer 當視覺驗證。

## 沉澱：接觸正確與人體自然度要分開驗收

IK 負責接觸幾何，不能代替人體發力設計。下一輪建議採「真人參考 → 關鍵姿勢 → 節奏／曲線 → 正常與慢速循環比對」，先看簡單人體輪廓，再處理服裝與次要擺動。可考慮用 AnimationPlayer 編輯主要姿勢，程式維持手腳接觸與碰撞；必要時增加肩背／脊椎的表現能力。

以上是後續改善建議，本次仍使用 `rig.gd` 程序關鍵點，尚未導入 AnimationPlayer、增加骨骼、網格蒙皮或真人動作資料。
